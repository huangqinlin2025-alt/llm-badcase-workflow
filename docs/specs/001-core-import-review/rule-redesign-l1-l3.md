# RULE-001 修订提案：L1 / L2 / L3 分层 Badcase 规则

- 状态：已确认，可作为 RULE-001 实现依据
- 依据：`Badcase入库逻辑.docx` 已转换为 `Badcase入库逻辑.md`
- 日期：2026-09-07
- 替代对象：当前 `pipeline.py` 的“绝对低分 / 人机分歧 / 机检 LLM 冲突 / 维度离群”平铺式信号模型

## 1. 核心调整

新规则不再把四类信号直接映射为 `P0/P1/P2`，而是先判定指标层级：L1 底线、L2 基础、L3 进阶。单条样本命中多层时，按 `L1 > L2 > L3` 定性；P0/P1/P2 仅是处理优先级，不替代业务层级。

| 层级 | 含义 | 初步结论 | 默认人工复核 | 默认处理优先级 |
| --- | --- | --- | --- | --- |
| L1 底线 | 安全、格式硬约束、任务边界、信息忠实/采信规则 | 底线劣化候选 | 100% | P0 |
| L2 基础 | 输入理解、指令遵循、场景适配、冲突处理等核心能力下降 | 能力缺陷候选 | 50%，优先核心场景与大分差 | P1 |
| L3 进阶 | 内容质量、差异化、表达体验和多样性下降 | 体验不佳候选 | 10%–20%，优先集中劣化 | P2 |

`candidate` 表示本次评测中待判断的版本，`baseline` 表示比较基准。规则表达统一使用：

\[
\Delta_d = score_{candidate,d} - score_{baseline,d}
\]

对于购物神评受控 AB 报告：`candidate=A=HY-Vision-2.0-instruct=优化后 Prompt`，`baseline=B=quinta_gouwushenping_firstround=优化前 Prompt`。因此 \(\Delta_d < 0\) 才表示优化后版本劣化。原文中的“B vs A”属于其模板记法，不能直接套用到当前购物神评映射。

## 2. 当前四类信号的重定位

| 现有信号 | 当前问题 | 新规则中的位置 | 是否可单独自动入库 |
| --- | --- | --- | --- |
| 绝对低分 | 将所有维度使用统一 `<=4` / 平均 `<6`，未区分底线、能力和体验 | L1/L2/L3 各自的合格线或优秀线证据 | L1 仅在硬规则证据明确时；L2/L3 否 |
| 人机分歧 | 当前直接影响 P1，混淆“输出问题”和“评测体系问题” | `评测分歧`，按 L1/L2/L3 触发不同复核路径 | 否；仅产生复核任务与评测体系标签 |
| 机检 LLM 冲突 | 当前硬编码 LLM 第一维为 D1，通用文件不可靠 | L1 `评测分歧`；按规范化维度名或机检硬规则判断 | 否；需人工/对账确认 |
| 维度离群 | 当前单条低于场景均值 2 分即入库，未分 Prompt 阶段和批量价值 | L3 批量集中劣化证据；基线按场景、候选版本、维度分层 | 否；需同时满足批量占比或抽样复核 |

当前 `engine.py` 的硬伤、格式软违规和 AB 劣势需要重分类，而不是直接照搬：

- `hard_fails` 非空：L1 硬规则候选，直接进入 100% 人工事实复核；人工确认后才为确认型 L1 Badcase。
- `violations`：L1 规则提示，但单独命中不自动入库；必须与硬规则、显著劣化或批量复现等独立证据叠加。
- AB 比较：是 L2/L3 的主要比较输入，不是独立于层级的第五类 Badcase。

## 3. 层级映射配置

规则必须按“评测量表配置”映射维度，不允许再使用 `values[0]` 代表 D1。每个评测配置需要声明：维度名、层级、是否硬规则、合格线、优秀线、显著劣化阈值和最小样本数。

### 3.1 购物神评首轮受控 AB 报告

| 报告维度 | 建议层级 | 用途 | 当前可用数据 |
| --- | --- | --- | --- |
| 输入理解与采信逻辑 | L2 | 核心能力对比 | A/B LLM 分数、理由 |
| 内容质量 | L3 | 表达与体验对比 | A/B LLM 分数、理由 |
| 差异化与角色分工 | L3 | 多样性与策略对比 | A/B LLM 分数、理由 |
| 输出格式合规 | L1 候选 | 格式硬约束筛查 | A/B LLM 分数、理由；缺少独立机检明细 |
| 安全红线 | L1 候选 | 安全底线筛查 | A/B LLM 分数、理由；缺少独立安全规则结果 |

加权总分、`差值 (A−B)` 和 `胜出方` 只作为 AB 汇总证据和排序依据；不得与五个原始维度一起再计算均分。

### 3.2 必须由业务确认的参数

文档给出层级原则，但没有给出全部量化阈值。以下参数不得凭代码默认值替代业务决策：

| 参数 | 建议初始值 | 需要确认的原因 |
| --- | --- | --- |
| L1 评分筛查线 | LLM 维度分低于 `6.0` 时仅标记为人工复核候选；确认仍需硬规则或人工事实核对 | L1 是零容忍硬规则，LLM 评分不能单独确认事实违规 |
| L2 合格线 | `6.0` | 低于合格线为 L2 劣化证据 |
| L2 显著劣化阈值 | \(\Delta \le -1.5\) | 相对基准版显著下降 |
| L3 劣化阈值 | \(\Delta < 0\) 作为候选；\(\Delta \le -0.5\) 作为优先抽样 | 体现“低于基准版”，并控制人工复核顺序 |
| L3 优秀线 | 原始 L3 维度均值 `>=6.8` | 未达 `6.8` 可作为 L3 劣化候选；不使用加权总分重复计算 |
| L3 批量门槛 | 同类场景/版本组劣化率 `>=20%` | 用于 B 级价值判定 |
| L2 高价值门槛 | 同类场景错误占比 `>=30%` | 用于 A 级价值判定 |
| L1 S 级复现门槛 | 同类场景稳定复现率 `>=60%` | 用于 S 级价值判定 |
| 离群最小样本数 | 每个基线组 `n>=10` | 小样本不启用离群信号 |

## 4. 建议的判定流程

### 4.1 自动初判

1. 读取量表配置，按 A/B 或 candidate/baseline 方向计算各维度 \(\Delta\)。
2. L1：读取硬规则明细、格式/安全评分与理由，生成 `L1_SUSPECTED`；不因单一 LLM 分数自动确认为底线违规。
3. L2：任一 L2 维度显著低于基准版，或低于 L2 合格线，生成 `L2_DEGRADED`。
4. L3：任一 L3 维度低于基准版，或整体未达优秀线，生成 `L3_DEGRADED_CANDIDATE`。
5. 以最高命中层级确定初步层级；保留全部触发维度、AB 差值和理由。
6. 单独计算 `评测分歧`：人工与 LLM、机检与 LLM 或规则与量表冲突。分歧不覆盖层级结论，改写为复核策略。

### 4.2 人工复核分流

| 初步层级 | 人工任务 | 入库前条件 |
| --- | --- | --- |
| L1 | 100% 事实复核，只确认是否触线 | 人工确认或机器硬规则可复现 |
| L2 | 50% 抽样；优先核心场景、\(|\Delta|\) 大、高频 query | 确认真劣化，或标记标准歧义 |
| L3 | 10%–20% 抽样；优先集中劣化场景 | 确认体验下降且非纯偏好；单条偶发通常排除 |

### 4.3 复核结果与最终归属

最终标签必须拆分存储：

```text
metric_level: L1 | L2 | L3
assessment_relation: llm_only | confirmed | disputed | standard_ambiguity | subjective_preference
badcase_type: confirmed_rule_violation | confirmed_capability_defect | confirmed_experience_issue | evaluator_defect | excluded
value_grade: S | A | B | EXCLUDED | PENDING_AGGREGATION
priority: P0 | P1 | P2 | NONE
```

- L1 分歧：优先归为评测体系 Badcase，人工确认后补规则边界集。
- L2 分歧：进入交叉复核；真劣化属于模型 Badcase，标准歧义补量表细则。
- L3 分歧：默认不作为模型 Badcase；按月统计分歧率，批量集中时作为评测锚点优化证据。

## 5. 优质 Badcase 价值等级

自动系统先输出 `PENDING_AGGREGATION`，不在单条判定阶段直接颁发 S/A/B。聚合任务按场景、维度、Prompt 版本、根因标签计算复现率和错误占比后确定：

| 层级 | 等级 | 条件 | 动作 |
| --- | --- | --- | --- |
| L1 | S | 人工确认 + 同类复现率 `>=60%` + 非外因 | P0，规则/安全紧急修复与回归集加固 |
| L1 | A | 人工确认 + 典型边界 + 可补规则盲区 | P1，补边界用例与规则 |
| L2 | A | 确认真劣化 + 同类错误占比 `>=30%` + 核心高频场景 | P1，进入模型优化和主力回归集 |
| L2 | B | 确认真劣化 + 有复现性 + 中频通用场景 | P2，常规迭代 |
| L3 | B | 确认体验下降 + 场景批量出现 `>=20%` + 非个人偏好 | P2，批量表达优化 |
| L3 | EXCLUDED | 单条偶发、纯偏好、无共性 | 不入精选库，仅留审计记录 |

## 6. 对现有数据模型和接口的影响

`RULE-001` 需要新增/扩展而非仅改阈值：

1. 为 `aligned_cases.payload_json` 引入 `metric_profile`、`source_label`、`prompt_stage`、`ab_evidence`、规范化维度映射。
2. `candidates` 增加或以 `evidence_json` 保存层级、初判状态、触发维度、基线/候选分、差值、复核策略和价值等级状态。
3. 新增批量聚合查询/任务，用于计算 `>=60%`、`>=30%`、`>=20%` 门槛；不能在单条 `judge()` 中虚构复现率。
4. 审核 API 后续应支持层级化结论：确认、评测误判、标准歧义、主观偏好，而不只有采纳/驳回。
5. 大库至少展示：指标层级、初判/复核结论、触发维度、A/B 差值、复核策略、价值等级状态、归因方向。

## 7. 已确认的实现决策

- [x] L1 只接受硬规则证据或人工事实确认；LLM 评分低于 `6.0` 仅触发 L1 复核候选。
- [x] L2 合格线为 `6.0`，显著劣化阈值为 \(\Delta \le -1.5\)。
- [x] L3 使用 \(\Delta < 0\) 作为候选、\(\Delta \le -0.5\) 作为优先抽样，原始 L3 维度均值优秀线为 `6.8`。
- [x] 离群保留为 L3 辅助证据，仅在基线组 `n>=10` 时启用。
- [x] AB 维度劣化是 L2/L3 的主规则；旧版“AB 显著劣势”不再作为平行独立信号。
- [x] 首期不自动计算 S/A/B 最终等级；统一先标记 `PENDING_AGGREGATION`，待聚合任务依据 60%/30%/20% 门槛确认。
- [x] 默认复核比例固定为 L1 100%、L2 50%、L3 10%–20%；后续可由场景配置覆盖。
