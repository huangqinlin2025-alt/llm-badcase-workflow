## 开发纪律

1. `main` 只接受通过测试的合并；实现使用 `feat/<issue>` 分支。
2. 每项任务开始前更新本任务相关规格；需求变更先修改规格和验收，再写代码。
3. 每项任务完成时执行对应测试并在 `acceptance.md` 记录命令、结果和已知限制。
4. 不在没有 SQLite 事实/Outbox 的情况下直接让前端或 CLI 写企微。
5. 不将生产数据、Token、SQLite 数据库、真实企微链接或用户内容提交 Git。
